# CRM Автосервиса (crmauto)

Облачная SaaS-система управления СТО, шиномонтажом, запчастями и авторазбором.

**Источник требований:** мастер-ТЗ v5.0 (основной документ). Этапы отмечаются в `docs/ROADMAP.md`; запреты и инварианты — в `AGENTS.md` и `docs/DOMAIN_INVARIANTS.md`.

## Архитектура
- Backend: Django/DRF, PostgreSQL как источник истины.
- Frontend: React + TypeScript.
- Redis/Celery: будущие фоновые задачи, архитектура событий через outbox.
- Каждый запрос ограничен компанией на серверной стороне; никакого доверия к tenant_id из тела запроса.
- Платежи, списания и закрытия операций проводятся только транзакционными командами.

## Разработка
Разработка непосредственно в `main`, без GitHub Actions. Проверки запускаются локально и вручную перед публикацией. Статус каждого спринта — в `docs/sprints/`. Пока критерии коммерческой готовности не выполнены, приложение не следует использовать для реального финансового учёта.

Код S01–S14 опубликован частично, но полный продакшен-контур не подтверждён. Нельзя проводить реальные платежи, оформлять фискальные чеки или обещать соответствие бухгалтерскому учёту только на основе внутреннего журнала CRM.

**Изолированный staging:** `scripts/commercial_acceptance.sh` (требует `CONFIRM_DISPOSABLE_STAGING=YES`, PostgreSQL, Redis, npm lockfile и переменные среды). Успешный прогон не подтверждён. Полный результат аудита: `docs/RELEASE_AUDIT_2026-10-19.md`.

**SaaS:** в production подписка по умолчанию ограничивает изменяющие API. Перед обновлением существующим организациям необходимо предварительно выдать корректные подписки, иначе они останутся в режиме чтения. При создании новой компании API назначает 14-дневный пробный тариф.

**Регистрация:** вход по подтверждённой почте и восстановление реализованы под `ENABLE_EMAIL_ONBOARDING=1`. До настройки SMTP, HTTPS и тестирования доставки регистрация выключена. Ручное начисление наличных — не банковская или фискальная операция.

**Доставка интерфейса:** `compose.production.yaml` добавляет Nginx/React-контейнер за внешним доверенным TLS-прокси. Для воспроизводимой сборки нужен отсутствующий пока `frontend/package-lock.json`; отсутствие файла намеренно блокирует production Dockerfile.
