# S36–S37: условия обслуживания и решения клиента

## S36 — текущая реализация
- `ServicePolicy` как история публикаций условий обслуживания и гарантии по SaaS-организации.
- Только owner/manager могут публиковать новые редакции; операции идемпотентны; повторение неизменённого текста блокируется.
- Текущая редакция единственная на организацию (ограничение PostgreSQL).
- Настройки React позволяют заполнять и публиковать тексты, видеть историю.
- Печатный заказ-наряд может включать действующие условия обслуживания; гарантийная памятка требует опубликованной редакции и фиксирует её текст в историческом снимке.
- Без юридической экспертизы текста это не равно соответствию законодательству.

## S37 — текущая реализация
- `POST /api/v1/portal/orders/<uuid>/estimate-decision`: только авторизованный клиент с **предварительно подтверждённым активным PortalGrant**, связанный с данным customer и organization.
- Решение approve/reject по строго указанной версии submitted Estimate; устаревшая версия отвергается, повторная попытка после смены статуса отвергается, пересечения tenant отвергаются.
- Атомарная запись approved_at, approval_method=authenticated_customer_portal, аудита и статуса WorkOrder.
- Никакой электронной подписи, SMS/OTP, доказательства доставки предложения, проверки личности сверх PortalGrant и юридического согласия это НЕ создаёт.
- Дополнительные работы при уже идущем ремонте остаются несогласуемыми клиентом; API согласования S37 распространяется лишь на первичную submitted-смету.
