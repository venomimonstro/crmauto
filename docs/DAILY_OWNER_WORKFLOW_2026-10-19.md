# Ежедневная операционная модель владельца СТО — 2026-10-19

Статус: сценарный анализ кода, **НЕ** доказанный интеграционный запуск. Продукт пока NO-GO для коммерческого использования.

## Роль владельца — ежедневная работа, а не первоначальная настройка

**07:45 открытие смены.** Руководитель проверяет график механиков/приёмщиков, свободные посты, просроченные ремонты, сегодняшние записи, ожидаемые поставки и наличие расходников. Должны быть события опоздания/отсутствия, назначение ответственных и перенос работ. Сейчас: Shift и Appointment есть; назначения задания механику, табеля и переносов нет.

**08:00–11:00 приёмка.** Звонок/онлайн-запись → поиск существующего владельца/автомобиля → создание или подтверждение записи → прибытие → акт приёмки с фото/дефектами/пробегом → заказ-наряд. Сейчас: запись/прибытие/заказ есть, полноценные фото, подписанный акт и клиентский онлайн-канал отсутствуют.

**09:00–15:00 производство.** Диагностика → позиции работ и материалов → согласование → назначение механика → резерв запчастей → закупка при нехватке → приёмка → выдача запчастей → выполнение и контроль качества. Сейчас: смета, резервы, закупка и проверки статусов есть; нет операций по заданиям, привязки резерва к строке сметы, реального клиентского одобрения и дополнительного согласования в процессе.

**12:00–18:00 расчёт.** Финальная сверка факт-план и рекламаций → начисление → частичная/полная оплата → чек/закрывающие документы → выдача авто и уведомление клиента → гарантия. Сейчас: внутреннее начисление, наличные и возвраты в журнале; не подтверждены ККТ/эквайринг/чек; выдача программно блокирована.

**18:00 закрытие дня.** Проверяются деньги, смены, невыполненные записи, зависшие работы, недостачи, дебиторская задолженность, закупки и прибыль по закрытым заказам. Сейчас: добавлен API `GET /api/v1/reports/daily?branch_id=<UUID>` и сводка на экране отчётов; фактическое закрытие кассовой смены, сверки, журнал отклонений, себестоимость и валидная прибыль отсутствуют.

**Еженедельные/месячные действия.** Зарплаты механикам, премии, остатки и инвентаризация, возвраты поставщикам, гарантийные ремонты, повторные визиты, загрузка постов, удержание клиентов, расчёт маржи и налоговые данные. Нельзя считать завершёнными до документарной и финансовой интеграции.

## Отдельные сценарии проблем
- Две записи на один пост в пересекающееся время — 409.
- Одновременная выдача зарезервированной детали — проверять PostgreSQL и повторный ключ.
- Продажа б/у детали дважды — запрещать переходами состояния и транзакционными блокировками.
- Мастер добавляет работы после согласования — должно потребовать нового доказанного одобрения, сейчас заблокировано.
- Кассир фиксирует карточный платёж без PSP — отказ.
- Авто готово, долг не закрыт — правила выдачи требуют юридического согласования и документов, сейчас выдача заблокирована.
- Клиент другого СТО пытается читать заказ → 404.
- Уволенный сотрудник вызывает API → 404.
