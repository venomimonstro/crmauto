# Аудит CRM Auto — 2026-10-19 — STATIC REVIEW, NO LIVE E2E

## Статус
NO-GO для продажи. Исходный код изучен в main, но Django/PostgreSQL, npm build, браузерная сессия, сетевой стенд, бэкапы и восстановление НЕ проверены на рабочей системе. Сценарии ниже — прохождение связей по коду, а не исполненные интеграционные тесты.

## Путь покупателя SaaS
1. Открывает сайт → публичная регистрация закрыта (identity/views.py) — P0.
2. Покупает тариф → модели Plan/Subscription, GET status есть, PSP-интеграция отсутствует — P0.
3. Срок оплаты истёк → billing/views.py возвращает read_only, но рабочие API пока не блокируют POST/PATCH — P0.
4. Сотрудники → нет полного механизма инвайтов, контроля лимитов и MFA — P0.
5. Импортирует существующую базу → CSV ограничен и частичный, нет полноценного мастера миграции — P1.

## Путь владельца СТО
1. Создание организации/филиала API существует, frontend поддерживает базовый онбординг.
2. Заводит клиента и автомобиль — API и UI есть, нет полноценной дедупликации и подтверждения владельца — P1.
3. Запись — пост и конфликт времени проверяются сервером; графики и сложные переносы отсутствуют — P1.
4. Визит → заказ-наряд → смета → согласование: код есть; approval_reference вводится сотрудником, а не подтверждается клиентом. Риск ложного согласования — P0.
5. Запчасти → резерв и выдача разделены; партии, себестоимость, корректировки и связь с конкретной строкой сметы не завершены — P0.
6. Закупки → часть приёмок попадает на склад, но нет достоверных первичных документов и возвратов поставщику — P0.
7. Деньги → начисление и ручная запись поступления могут расходиться с реальным PSP/ККТ/банком; без фискализации нет коммерческого закрытия — P0.
8. Выдача машины специально заблокирована до полной финансовой логики, реальный рабочий день не закрывается — P0.
9. Отчёты показывают начисления, ручные движения и долг. Не показывают достоверную прибыль — корректное ограничение.

## Авторазбор / шины / портал
- S10: уникальные б/у детали и резерв есть; факт продажи/возврата, затраты и документы о приобретении донора неполны — P0.
- S11: шины клиентов отделены от товарного склада (верно); нет актов ответхранения и начисления услуг — P1.
- S13: portal grants inactive by default (верно). Выявлено ослабленное связывание прав пользователя с организацией заказ-наряда, исправлено точной проверкой organization/customer/user через Exists — исправление требует интеграционного теста.

## Проблемы платформы
- P0: нет доказанных запусков manage.py check, makemigrations --check, migrate, backend tests, npm build и браузерного E2E.
- P0: subscription read_only не enforced на всех изменяющих API.
- P0: отсутствие подтверждённого end-to-end signup → payment → operation → fiscal receipt → closure.
- P0: нет подтверждённого восстановления из резервной копии, RPO/RTO — неизвестны.
- P0: нет подтверждённого MFA и антизлоупотребления на production администраторах.
- P1: один глобальный SELECT FOR UPDATE на организацию для команд ограничивает конкурентность;
  добавить стресс-тесты и пер-aggregate locking.
- P1: нет доказанного соответствия модели БД файлам миграций.
- P1: frontend отсутствуют некоторые ключевые действия и корректный единый UX-поток между модулями.
- P1: аудит документов и доказательств согласования не удовлетворяет полноценному электронному документообороту.

## Правило GO / NO GO
Переход в коммерческий запуск только при: зелёных миграциях и тестах на PostgreSQL,
сквозных браузерных E2E, интеграции PSP/ККТ, принудительной SaaS-политике,
проверке tenant isolation, обработке инцидентов и тренировке восстановления.
