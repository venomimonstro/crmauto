# Протокол коммерческой приёмки — 2026-10-19

Статус: **NO-GO**. Изменения исходного кода не означают прохождения миграций, браузерных тестов, эквайринга и юридической приёмки.

## Изменено в текущем этапе
- Пользователь-автор допускается к повтору только собственной ранее выполненной команды (защита idempotency replay).
- Серверная политика SaaS запрещает записи организаций без действующей подписки в режиме `BILLING_ENFORCE_WRITES=1`; у новых покупателей создаётся ограниченный trial.
- Регистрация по email opt-in, подтверждение адреса и восстановление доступа доступны только при настройке SMTP и HTTPS.
- Приглашение сотрудника отправляется на конкретную почту, содержит ограниченный по времени подписанный токен, активируется только тем же аутентифицированным пользователем; доступ отзывается на уровне tenant Membership.
- Pending-инвайты занимают места в тарифе; менеджер не может назначать менеджера; сотрудник назначается на филиал.
- Запрет выдачи данных владельца автомобиля кассиру через общий поиск и ограничения ответов для механика/кладовщика.
- Карточные/банковские поступления не считаются подтверждёнными без PSP. Внутренний журнал наличных не равен фискальной онлайн-кассе.

## Предварительная проверка на отдельной машине с Docker и PostgreSQL
Никогда не запускайте проверки на единственном production-хранилище без резервной копии.

1. Снимите и проверьте резервную копию БД и файлов.
2. Поднимите disposable PostgreSQL/Redis; создайте отдельные `DATABASE_URL`, `REDIS_URL`, `DJANGO_SECRET_KEY` (не публикуйте секреты).
3. Установите `backend/requirements.txt`, затем выполните:
   - `python -m compileall -q backend`
   - `cd backend && python manage.py check --deploy`
   - `python manage.py makemigrations --check --dry-run`
   - `python manage.py migrate --noinput`
   - `python manage.py test --verbosity 2`
4. В `frontend`: `npm install --no-audit --no-fund && npm run build`.
5. Проверьте живой интерфейс в Chrome/Firefox и мобильном Chrome при медленном соединении.
6. Временно включите тестовую доставку писем, имитируйте signup→verify→login→создание организации→приглашение сотрудника→принятие→отзыв доступа.
7. Настройте реальный SMTP/HTTPS только после проверки SPF/DKIM/DMARC и доставки в вашу доменную почту.
8. Убедитесь, что `BILLING_ENFORCE_WRITES=1` и каждый действующий клиент имеет валидную подписку до развёртывания.
9. Прогоните тесты из `backend/core/test_owner_journey.py`, `backend/billing/tests.py`,
`backend/identity/test_invitations.py`, `backend/crm/test_privacy.py`, `backend/portal/tests.py`.
10. Проведите восстановление БД и файлов на независимом стенде и замерьте RPO/RTO.

## Бизнес-сценарий покупателя SaaS
Ожидается: почта подтверждена; trial 14 дней создан; 1 филиал создан; второй филиал blocked;
два приглашения в пределах лимита 3 сотрудников; третье blocked; неподтверждённая почта/украденный инвайт blocked;
истёкший trial запрещает изменение и оставляет чтение;
владельцу доступны сведения подписки; продление *только* после проверки PSP/webhook (пока не реализовано).

## Бизнес-сценарий владельца СТО
Ожидается: клиент+авто→запись→нет наложения постов→визит→наряд→смета;
ремонт до согласования blocked; согласование требует основание; приход запчастей подтверждён;
резерв <= остатков; выдача <= резерва; начисление по смете; частичная наличная оплата;
переплата blocked; неподтверждённая карточная оплата blocked; выдача автомобиля
до законного кассового/документарного контура blocked (не скрывать ограничение).
